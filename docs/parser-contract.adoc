= Amath parser contract
:toc:

The link:stage-contract.adoc[shared stage profile] defines the model-based
target for amath, latexmath and unicodemath: one public `parse` API returning
the typed LML language model, with raw parsing internal to tests and tooling.
It owns the common preprocessing, engine, error, artifact, corpus-pin and
release requirements.

This document describes amath's implementation of that profile. The typed
model replaces amath 0.1's raw-tree return value: it is a breaking change,
released as 0.2.0, and a published Plurimath release pinning `amath ~> 0.1.0`
or already using the typed model must come before amath 0.2.0.

AsciiMath-specific notes: input needs no language preprocessing; the decimal
entries are `dot`, `comma` and `arabic`; shared-exponent captures and exact
source-text behavior are described below.

Runtime dependencies on this main revision: `parsanol ~> 1.3, >= 1.3.131`
and `lutaml-model ~> 0.8, >= 0.8.162`. amath never requires Plurimath or
reads Plurimath constants.

== API

[source,ruby]
----
Amath.parse_model(input, decimal: ".", engine: :auto) # => Amath::Model::Document
Amath.parse_model(input, dialect: :pma)               # => Amath::Model::PmaDocument
Amath.parse(input, decimal: ".", engine: :auto)       # => raw tree (amath 0.1 contract)
Amath.last_engine                                # => :native, :ruby or nil
Amath.native_available?                          # => true / false
Amath.artifact_path                              # => String
Amath.artifact_path = path                       # tests and tooling only
Amath::VERSION
----

`input`:: a `String`. Non-UTF-8 strings are transcoded to UTF-8; a string that
is not valid UTF-8 (or cannot be transcoded) raises `ArgumentError`. amath does
no preprocessing: the caller passes the exact string to parse, and every
position refers to that string.

`decimal`:: the decimal marker for numbers. See <<decimal>>.

`engine`:: `:auto`, `:native` or `:ruby`. See <<engine>>.

`dialect`:: `:legacy` (the default), dialect L, the AsciiMath this page
describes; or `:pma`, dialect P (<<pma>>). Any other value raises
`ArgumentError` before an artifact is loaded.

There is no second public parse method. The raw parse tree is internal
(<<raw-tree>>).

=== Successful result: the typed model

`Amath.parse_model` returns an `Amath::Model::Document`, a LutaML Model object:

`expression`:: the expression, an `Amath::Model::Expression`; `nil` for
empty input (`""`), the declared empty representation.
`decimal`:: the decimal marker the input was parsed with.

The model classes live under `Amath::Model`. Apart from `Document` and
`MathSymbol` (`lib/amath/model.rb`) they are generated from the grammar by
`scripts/generate_model.rb` into `lib/amath/model/nodes.rb`, one class per
capture of the normalized grammar (<<normalization>>):

* a capture that holds a node is a class with one attribute per key it can
  hold;
* a capture that holds a list is a collection of `<Capture>Item` elements;
* a capture that holds text is a `String` attribute, the text as written.

So an attribute has the same name and type wherever it occurs. A run of
terms (a sum, a sequence) is one `expr.amath_chain` collection of
`AmathChainItem` elements (`amath_step`, `amath_lr`, and a closing
`amath_end`), not a nesting one level per term: a 3000-term sum is a list of
6000 items.

Numbers keep their source text, decimal marker included: under
`decimal: ","`, `1,5` is the number text `"1,5"`. There is no float
conversion anywhere in the model.

The text of a catalog capture (`symbol`, `comma`, the parens `lparen`,
`rparen`, `left`, `right`, `table_left`, `table_right`, and the `d`/`x` of a
differential) is an `Amath::Model::MathSymbol`: `spelling` is the text as
written, and `value` (the Unicode text) and `kind` (`symbol`, `open`,
`close`, `paren`, or `unlisted` for text the catalog does not list) are
derived from it through `Amath::Symbols`. The catalog is
`data/asciimath-symbols.json`, exported once by `scripts/export_symbols.rb`
from the Plurimath revision the grammar was transcribed from; it records each
spelling's Unicode value, MathML element, kind and Plurimath class, so the
Plurimath mapper can map symbols without a lookup of its own.

Uncertainty calls are `Amath::Model::Uncertainty` objects whose fields
(`uncertainty_class`, `value`, `magnitude`, `lower`, `upper`,
`concise_digits`, `shared_exponent`, `coverage_factor`,
`coverage_probability`, `interval_kind`, `unit`) are the source texts.

Wrapper attributes (`literal`, `literal_2`, `list`, `empty`, `empty_list`)
come from the shape normalization: `literal` holds text where the same slot
can also hold a node, `empty` and `empty_list` mark an optional part that
matched nothing.

`model/asciimath.lml.json` is the LML export (`Lutaml::Model::Lml.export`,
verified) of every model class; `scripts/generate_model.rb --check` in CI
requires both the classes and the export to match a fresh generation.

The model is read through its attributes. Serializing it through a
LutaML format (`to_hash`, `to_yaml`) is not supported: lutaml-model 0.8.162
compiles a serialization transformation for every path through the
recursive class graph, which does not finish for this model.

=== Shared exponents in uncertainty calls

An uncertainty call can put its measured fields in a group followed immediately
by `e` and a signed or unsigned integer exponent:

[source,asciimath]
----
ustd((3.85, 0.23)e4)
ustd(680(41)e-3)
uexp((3.85, 0.23)e+4, 2, 0.95)
ucov((1.024, 0.983, 1.088)e-3, 0.95, shortest)
----

These forms set `shared_exponent` on the `Uncertainty` model (in the raw
tree, a `shared_exponent` key in the `uncertainty` hash). Its value is the
source text of the exponent digits and optional sign, without the `e`. All
mantissas, concise digits, units and dimensionless coverage fields remain
unchanged source texts (raw-tree slices keep their byte offsets). Calls
without an exponent are unchanged.

The consuming reader shifts the decimal point exactly in the value and
magnitude, or in the value and both interval endpoints. For concise notation,
it first derives the magnitude from the mantissa's decimal places. Thus
`ustd(680(41)e-3)` means value `0.680` and magnitude `0.041`.
Coverage factors and probabilities are not scaled. No float conversion is
needed, and amath does not replace source slices with calculated text.

Whitespace before `e`, incomplete exponents and a minus sign on a magnitude
remain outside the uncertainty syntax and follow the ordinary grammar fallback.
The separate expression-language forms `(3.85 +/- 0.23)e4` and `680(41)e-3`
remain ordinary AsciiMath here; this extension uses explicit uncertainty calls.
The input/tree and consuming-reader decimal expectations are recorded in
`corpora/uncertainty-shared-exponent.yml`.
`scripts/generate_stage_cases.rb` turns each corpus file into a raw-tree
payload for the `asciimath` stage generations in plurimath-testsuite, after
checking that both engines return the same tree and that it carries the
corpus texts. With `--boundary typed-model` it writes `model-<group>`
payloads instead: the `Amath.parse_model` Document of each case, written from the
bound data the model is built from and typed by the declared model classes
(`model/asciimath.lml.json`), after checking that both engines agree and that
the built model gives the same rows. Its `--producer` option writes the
provenance block for that generation, including the LML export checksum for
typed-model rows.

[[decimal]]
== Decimal markers

The artifact carries one entry per supported marker. `decimal:` selects the
entry; there is no locale lookup inside amath.

[cols="1,1,2"]
|===
| `decimal:` | Artifact entry | Marker

| `"."` (default) | `dot` | FULL STOP, U+002E
| `","` | `comma` | COMMA, U+002C
| `"٫"` | `arabic` | ARABIC DECIMAL SEPARATOR, U+066B
|===

Any other value raises `ArgumentError` before the artifact is touched. An
artifact that lacks any of the three entries is rejected with
`Amath::ArtifactError`.

[[engine]]
== Engine policy

Parsanol has a native (Rust) engine and a pure-Ruby engine. Its own
`mode: :native` silently runs the Ruby engine when the extension is missing,
so amath decides the engine itself before calling Parsanol:

[cols="1,3"]
|===
| `engine:` | Behaviour

| `:auto` (default)
| Native if `Parsanol::Native.available?`, otherwise Ruby. Input nested too
  deeply for the native engine (see <<deep-nesting>>) is parsed again with the
  Ruby engine.

| `:native`
| Native. If the extension is not available, raises
  `Amath::EngineUnavailable`; never runs Ruby instead. Input nested too
  deeply for the native engine raises `Amath::NestingTooDeep`; never runs
  Ruby instead.

| `:ruby`
| Ruby engine only; the native extension is not called.
|===

After every call that reaches the parser (success or `ParseError`),
`Amath.last_engine` returns the engine that produced the result, `:native` or
`:ruby`: under `:auto` it is `:ruby` when deep input was parsed again with the
Ruby engine. The value is thread-local; it is `nil` on a thread that has not
parsed yet.

Limits of what `last_engine` proves:

* It records the engine amath ran. Inside `Parsanol::Native.parse`,
  Parsanol may still run its interpreter for grammar constructs native cannot
  express (custom atoms). The amath grammar is expected to contain none; the
  differential check in `scripts/check.rb` is where internal fallback is
  detected, not this flag.
* Parsanol 1.3.107 ships precompiled native extensions for x86_64 Linux on
  Ruby 3.2 to 4.0. CI runs Ruby 3.2, 3.3 and 3.4 on ubuntu-latest with the
  native examples required. Other platforms are not yet verified.

[[deep-nesting]]
=== Deep nesting

Parsanol's native engine stops at a fixed recursion depth ("Maximum recursion
depth (500) exceeded" or "Recursion limit exceeded: depth 1000"). With the
AsciiMath artifact that is about 110 levels of `(` and about 80 of `{`; other
constructs (`sqrt`, `/`, unary `-`) reach it at other depths. On a thread
other than the main one, the native call can also exhaust the thread's Ruby
stack (1 MiB by default) much earlier (at about 40 levels of `(` on x86_64 Linux); Ruby reports
that as `SystemStackError`.

Length is not depth. A run of terms (a sum such as `x + x + ... + x`, a
sequence of symbols, a comma list) is parsed as a repetition, not by one
nested rule call per term, so neither engine gets deeper as the run gets
longer. The model keeps that run as one flat `amath_chain` list, so it is
as shallow as the input's bracket nesting, whatever the number of terms.
(The internal raw tree is the legacy nested one, `{expr: term + {expr:
...}}`, one level per term, rebuilt without recursion by
`Amath::Renester`.) When the
input after a run fails to parse, the grammar falls back to its recursive
rule to find the same tree or rejection as before; such input can still
hit the limits below.

For such a recursion-limit failure Parsanol's own error path would reparse
the input through its Ruby interpreter with a diagnostic reporter, which on
deep input takes minutes or exhausts the stack. amath therefore hooks
`Parsanol::Native.raise_native_parse_error` (a prepended module, active only
on the current thread while amath's own native call runs) and stops at the
native failure. Then:

* `engine: :auto` parses the input with the Ruby engine (`last_engine` is
  `:ruby`), as it also does when the native call raises `SystemStackError`;
* `engine: :native` raises `Amath::NestingTooDeep` (`last_engine` is
  `:native`).

The Ruby engine has no fixed limit but is bounded by the Ruby stack. On the
main thread it parses 1,000 levels of `(`; rejecting deep invalid input needs
more stack, because Parsanol reparses it with its recursive interpreter to
find the position, so a rejection of input a few hundred levels deep can
raise `Amath::NestingTooDeep` instead of a positioned `ParseError`. amath
never lets `SystemStackError` escape from `Amath.parse` or `Amath.parse_model`.

== Errors

All deliberate errors inherit from `Amath::Error < StandardError`.

`Amath::ParseError`::
The input is not valid AsciiMath for the selected decimal marker (or, under
`dialect: :pma`, not valid pma; then `category` names the rule it breaks,
see <<pma>>; it is nil for dialect L). Full
consumption is required: a valid prefix followed by invalid text is a
rejection, never a partial tree. Attributes:
+
* `byte_offset` — zero-based UTF-8 byte offset of the deepest failure;
* `char_offset` — the same position in characters;
* `input` — the (UTF-8) string that was parsed.
+
The message text is for humans and is not part of the contract. The original
`Parsanol::ParseFailed` is available as `cause`.

`Amath::NestingTooDeep < Amath::ParseError`::
The input nests deeper than the engine that ran can handle: the native
engine's recursion limit under `engine: :native`, or an exhausted Ruby stack
under any engine. See <<deep-nesting>>. `byte_offset` and `char_offset` are
`nil`, since no rejection position was found; `input` is set. Whether such
input is valid AsciiMath is not known.

`Amath::ArtifactError`::
The artifact is missing, is not valid JSON, is not a JSON object, fails its
checksum, declares an unsupported shape, lacks a required entry, or cannot be
compiled or registered by the installed Parsanol. Raised under every engine
setting. amath never falls back to another artifact or grammar and never
recompiles anything except the artifact's own embedded source (Parsanol's
documented pure-Ruby path).

`Amath::EngineUnavailable`::
`engine: :native` was requested and the native extension is not available.

`ArgumentError`::
Unknown `decimal:` or `engine:`, non-String input, or input that is not valid
UTF-8.

== Positions: bytes versus characters

Parsanol reports positions in *bytes*; Parslet reported them in *characters*.
They differ as soon as the input contains non-ASCII text.

* In the internal raw tree, `Parsanol::Slice#offset` is a zero-based byte
  offset. Note that `Parsanol::Slice#charpos` is an alias of `offset` and is
  *also* a byte offset. The model holds source texts without offsets.
* `Amath::ParseError#byte_offset` is a byte offset and `#char_offset` is the
  character offset computed by amath.

Example: in `text(é) x`, the raw-tree leaf `x` has `offset == 9`, while it
is character 8. To convert a byte offset to Parslet's character offset:

[source,ruby]
----
char = input.byteslice(0, byte_offset).length
----

where `input` is the UTF-8 string passed to `Amath.parse` or `Amath.parse_model`.

Known difference from Parslet: the deepest rejection position can differ by
one. For `x 1.` the A0 spike measured Parslet's deepest failure at 3 and
Parsanol's at 4. The conformance corpus records the agreed position per case.

== Artifact loading

The artifact path defaults to `artifacts/asciimath.json` inside the installed
gem (`Amath::DEFAULT_ARTIFACT_PATH`). It is loaded and checksum-verified once,
on first use, and cached for the process. Assigning `Amath.artifact_path=`
clears the cache; it exists for tests and tooling, not for selecting
alternative grammars in production.

[[pma]]
== pma (dialect P)

`Amath.parse_model(input, dialect: :pma)` reads pma, the strict ASCII dialect
specified in plurimath `docs/pma.adoc` (amath#16). It parses with its own
artifact, `artifacts/pma.json` (grammar `grammars/pma.parg`, generated from
`grammars/pma.parg.template` and the registry's pma entries), and never with
the dialect L artifact; a refused input is never retried in the other
dialect. A missing or failing pma artifact raises `Amath::ArtifactError`.

Version 1 reads one term:

* a measured value: a measured literal `(v +/- u)`, with an optional shared
  exponent `(v +/- u)e4`, a relative uncertainty `(v +/- p%)` and an optional
  distribution tag inside the bracket, `(v +/- u ~rect)`; or a constructor
  `ustd(v, u)`, `uexp(v, U, k[, p])`, `ucov(v, lo, hi, p[, kind])`;
* a measured value followed by `unit(...)`;
* `unit(...)` on its own;
* `diff(...)` of a measured value with its unit.

The content of `unit(...)` is unquoted and parsed by the asciiunits artifact
(gem `asciiunits`). The pma artifact's checksum record names the asciiunits
artifact the grammar was composed with, and amath refuses to run pma with
another one (`Amath::ArtifactError`).

A unit may end with a quantity assertion, `unit(J::energy)`: `::` and the
English name of a unitsdb quantity, at most one, after the whole unit
expression. The names and their unitsml identifiers are in
`data/quantities.json`, written by `scripts/quantities.rb` from the unitsdb
version the Gemfile pins. An unknown name is refused as `quantity-assertion`.
The `quantity` of the `Amath::Model::Unit` holds the identifier (`q:energy`);
amath does not check that the quantity fits the unit.

The result is an `Amath::Model::PmaDocument` whose `term` holds
`uncertainty`, `unit` or `diff`. A measured value is the same
`Amath::Model::Uncertainty` class dialect L builds, with its unit in `unit`
(an `Amath::Model::Unit` whose `literal` is the unit text). pma adds three
fields that stay nil for dialect L: `plus_minus` (`+/-` for a measured
literal, which is a standard uncertainty), `relative_magnitude` (the `p` of
`p%`) and `distribution` (`rect`, `triang` or `arcsine`). Numbers keep their
source text. `decimal:` has no meaning in pma version 1; any value other than
`"."` raises `ArgumentError`.

Every form the specification leaves open is refused. Each refusal is an
`Amath::ParseError` with `byte_offset`, `char_offset` and a `category`: one
of `reserved-word`, `adjacency`, `constructor-arity`,
`constructor-argument`, `measured-literal`, `plus-minus-spelling`,
`shared-exponent`, `relative`, `distribution-tag`, `concise`,
`unit-expression`, `unit-attachment`, `quantity-assertion` (the specification's
taxonomy) or `no-production` (text that starts no production). The position
is the parser's; for a unit the asciiunits grammar refuses, it is the
position inside the unit text. `corpora/pma/*.yml` holds every accepted and
refused example of the specification, with the categories and positions,
and is staging until the pma corpus has its place in a testsuite.

The pma grammar has no recursion: brackets inside `unit(...)` nest at most
eight deep, so deep input is a `ParseError`, never `NestingTooDeep`.

[[registry]]
== The registry

`data/vocabulary.json` is the shared registry, format `amath-vocabulary/v2`
(amath#16). Each entry has a `category` (the grammar list it belongs to), a
`value`, a `dialect` (`legacy`, `pma` or `both`) and a `binding`, which names
the parse tree leaf (capture) the entry produces and the model type of that
leaf. `scripts/generate_grammar.rb` checks that every leaf of a dialect L
binding is a capture of the dialect L grammar.

The dialect L part is pinned by edition. The entries tagged `legacy` or
`both`, written back in the v1 layout, must give exactly the bytes whose
sha256 `legacy_edition` records, and the dialect L grammar is generated from
those bytes. An entry tagged `pma` never reaches it. A new dialect L
vocabulary comes from `scripts/export_vocabulary.rb` and enters the registry
with `ruby scripts/registry.rb --import-legacy FILE`, which pins it as the
next edition and keeps the pma entries. `ruby scripts/registry.rb --check`
verifies the file and the pin.

The pma grammar is generated from the entries tagged `pma` or `both` (in
version 1, the distribution names), checked with the same shape
normalization and strict checks as dialect L, and its header records the
registry edition and the asciiunits artifact (`units` in the registry). The
model is generated from both grammars (`scripts/generate_model.rb`): a
capture name is one class with the keys of both, and every binding's model
type is checked against the generated model.

The registry also lists the pma reserved words (`unit`, `ustd`, `uexp`,
`ucov`, `diff`, `quantity`). They are grammar terminals, not entries.
`scripts/check_reserved_words.rb` fails the build when one of them is a
spelling of any registry entry, or a unit symbol or unit name in unitsdb.
CI runs both checks.

[[normalization]]
== Grammar shape normalization

`scripts/generate_grammar.rb` expands `grammars/asciimath.parg.template`
with the pinned dialect L edition of the registry `data/vocabulary.json`
(see <<registry>>), reads every rule with Parsanol's PARG parser into
a rule tree (`scripts/parg_rule_tree.rb`) and normalizes capture shapes with
the shared rules N1-N7 of `scripts/normalize_shapes.rb` (the file unicodemath
and latexmath use, from the option-F proof of concept) and amath's rules N8
and N9 with its corrections to the shared rules (`scripts/amath_shapes.rb`). Under Parslet's
flattening one capture name can hold text, a hash or a list depending on the
alternative that matched; the rules only ADD captures (which never changes
what the grammar accepts) until every capture holds one kind:

N1 text alternative:: text in a node slot becomes `(x) as literal`.
N2 empty alternative:: `[x]` in a node slot becomes `x / "" as empty`.
N3 list in node slot:: a list in a node slot becomes `(x) as list`.
N4 list slot:: a capture of a repetition stays a list of nodes.
N5 text sibling:: text beside nodes in a sequence becomes `literal`,
`literal_2`, ...
N6 forced rule:: a rule that can return text or a node is normalized once,
at every call site.
N7 presence capture:: a capture of a lookahead gets `"" as present`.
N8 empty run:: a text run that can match nothing, at a named position,
becomes `(1*(x)) as literal / "" as empty_list` (the legacy tree held `[]`).
N9 catalog spelling:: catalog text becomes `((x) as spelling) as name`.

Generation stops when a capture still holds two kinds, or only ever holds
nil, and when a rewritten rule does not read back as its normalized tree.
Besides `grammars/asciimath.parg` it writes
`grammars/asciimath.wrappers.json` (the added captures and their kinds) and
`grammars/asciimath.normalized-rules.json` (the normalized rule tree, the
input of `scripts/generate_model.rb`). A capture that holds nil only when an
optional part at a named position did not match (an unclosed paren's
`rparen`) is a `nil` attribute.

[[raw-tree]]
== The raw tree

`Amath.parse(input, decimal:, engine:)` and `Amath::Parser.raw(input,
decimal:, engine:)` return the parse tree of the legacy Plurimath grammar,
exactly as amath 0.1's `Amath.parse` returned it (Hash/Array with
`Parsanol::Slice` leaves, a plain `""` for empty input). `Amath.parse` keeps
this amath 0.1 contract unchanged, keywords included (it takes no
`dialect:`), because released Plurimath 0.11 depends on amath `~> 0.1` and
walks this tree; the typed model is `Amath.parse_model`. `Amath::RawTree` builds it from the normalized grammar's tree: it
removes every wrapper capture listed in `grammars/asciimath.wrappers.json`,
re-running Parsanol's merge of sequence results, and `Amath::Renester`
rebuilds the legacy nesting of the flat chains. Parity is checked as
`Renester.call(unwrap(raw)) == legacy tree`.

== Declared bindings and regeneration

Each entry rule puts the whole expression under one `root` capture and
declares one binding for it, `root -> expression (any)`: the complete tree as
plain data. `Amath.parse_model` applies it (`Amath.bindings`, the paired Ruby
binding artifact) and builds `Document.new(expression: ...)`; lutaml-model
constructs the nested model from the declared attribute types, with no
hand-written tree walker.

`scripts/compile.rb` compiles the grammar with `--bindings all`, which writes
one declared binding artifact per Parsanol target beside the parse artifact:

* `artifacts/asciimath.bindings.ruby.json`
* `artifacts/asciimath.bindings.rs.json`
* `artifacts/asciimath.bindings.ts.json`
* `artifacts/asciimath.bindings.python.json`

The script loads each one with Parsanol's verifier (kind, checksum, target,
binding version) and pairs it with the parse artifact (grammar, version and
source hash). With `--determinism` it compiles again and requires identical
bytes for the parse artifact and all four binding artifacts.
`artifacts/asciimath.checksums.txt` records the sha256 of every file and the
Parsanol checksum and binding version of every binding artifact. Parsanol
1.3.130 and earlier accept `--bindings` but write no binding artifacts, so the
compiler bundle needs 1.3.131 or later.

The parse artifact also embeds the Unicode tables of the Ruby that compiled
it (its `unicode_tables` field), so identical bytes need the same Parsanol
version and the same Ruby. CI regenerates with both, read from the committed
files.
